## Questions the owner asked, with the short answer

| Question | Short answer |
| --- | --- |
| Analyse the choices (firewalld, ufw and so on) and how Foomuuri on nftables bridges gaps across distributions | The gap is in the managers, not the kernel. Foomuuri bridges it where it is packaged. The decision holds. See the analysis. |
| Why recommend the `foomuuri_dbus` change? | Before 0.31 any local user can change zones through the D-Bus handler. Ubuntu 24.04 has the fix only in Ubuntu Pro, the handler starts by default, and hosts with fixed zones do not need it. |
| Is this the job of a SWOT? | Partly. It fits a summary of Foomuuri alone, not the comparison of options and not a single risk decision. |
| What is recommendation 2? | Turn the D-Bus handler off by default. Done in the role, untested. |
| What is recommendation 3? | State the version policy per platform. Overtaken by the owner's decision not to rely on distribution packages for Foomuuri. |
| Is it better to build Foomuuri, or provide our own unified package? | Neither at first. Foomuuri is pure Python, so building is only packaging. Reuse Debian's `.deb`, with an own thin package as the route to one definition across families. |
| If nftables comes with the kernel and Foomuuri only compiles rules, what is the distribution issue? | It is thin. The `nft` command and Python are distribution packages with a version floor, package formats differ, and the distribution's package and an own one would claim the same paths. |
| Must the old firewall be removed before the Foomuuri one is installed? | No. Each manager has its own table and a drop in any table is final, so two firewalls together enforce the stricter of the two. Create first, then remove. |

## Findings worth keeping

- **Ubuntu 24.04's fix for CVE-2025-67603 and CVE-2025-67858 is only in Ubuntu Pro.** The public package is Foomuuri 0.22 without the fix. Per the research, Linux Mint 22 uses the same archive.
- **Foomuuri's D-Bus handler starts with the firewall by default.** `foomuuri.service` declares `Wants=foomuuri-dbus.service` in 0.22 and on `main`.
- **Package versions in the research were stale.** `trixie-backports`, EPEL 9 and the AUR carry 0.34, EPEL 10 carries 0.33, and Ubuntu 26.04 carries 0.31.
- **Foomuuri 0.22 parses `--set=etc_dir=`**, so the role's staged check works on the oldest version in scope.
- **Firewalls can overlap.** Each manager has its own nftables table, and a drop in any table is final, so two firewalls together enforce the stricter of the two.
- **A raw node that meets the contract has nothing to swap.** It already runs Foomuuri, so the role writes its fragment and reloads in one step.
- **For the firewall, onboarding changes who owns the configuration, not what the firewall does.**
- **The role's base rules assume SSH on port 22 from any source.** The contract's `ssh_port` and `ssh_sources` are not inputs to the role.
